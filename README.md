
# 写在前面
由于vivo 互传网页端（针对安卓设备）把原先无限制的局域网文件互传，改成了每天限制 500M 的云端互传。所以做这个项目就是为了把「局域网内想传多少传多少」的能力恢复回来


# 功能简介

用 APP 端扫码或扫描局域网。和电脑浏览器连接。在浏览器里浏览手机的照片 / 视频 / 音乐 / 文档，勾选后保存到电脑，也能反向把电脑上的文件发进手机。全部流量只走家里的网，不经任何公网或云端。

三端都是手写的最小实现：电脑端一个零依赖 Node 服务，网页端三个静态文件，手机端一个 Android APP。

---

## 组成

| 部分 | 路径 | 实现 |
| --- | --- | --- |
| 电脑端服务 | `server/index.js` + `server/lib/` | 纯 Node 标准库，无 npm 依赖、无数据库 |
| 电脑端网页 | `server/web/` | 原生 HTML/CSS/JS，无框架 |
| 手机端 APP | `phone/app/` | Java，唯一第三方库是 zxing（扫二维码） |
| 假手机（联调用） | `test/fake-phone.js` | 纯 Node，模拟一台设备跑完整协议 |
| 桌面启动器 | `tools/launcher/`、`启动互传.bat` | 双击启动，不留黑框 |

## 快速开始

1. **电脑**：双击 `启动互传.bat`，或在终端里 `node server/index.js`（需要 Node 18+）。启动后会打印网页地址和局域网 IP，默认端口 `8787`，发现端口 `8788`（可用环境变量 `PORT` / `UDP_PORT` 改）。
2. **手机**：浏览器打开 `http://<电脑IP>:8787/api/apk` 直接下载并安装 APK（minSdk 26，Android 8.0 起）。
3. **连接**：APP 打开后会在同网段广播探测，自动列出电脑；也可以扫网页上的二维码直连。
4. **使用**：电脑浏览器打开 `http://<电脑IP>:8787`，手机上保持 APP 在运行（它会起前台服务）。

## 功能

- 分类浏览（图片 / 视频 / 音乐 / 文档）与最近 30 天；每页 100 条，可一次「加载全部」
- 缩略图进视口才请求，4 个线程轮转，列表滑动不卡
- 排序（时间 / 名称 / 大小）与分类内关键字搜索——都要先把这一类加载完才解锁
- 勾选文件时顶栏实时显示「已选 N 项 · 总大小」
- 鼠标悬停显示完整文件名 + 文件大小
- **保存至电脑**（手机 → 电脑，支持批量）、**发送到手机**（电脑 → 手机）
- APP 端前台服务 + 通知栏进度；断线时留在连接页显示「重连中」，3 秒后自动重连
- 服务端命令行打印每台设备的连接与传输事件

## 工作原理

```
   手机 APP  ──── ①  命令通道（APP 主动长轮询） ────►  Node 服务  ──── ③ SSE/JSON ────►  电脑浏览器
       ▲                                                │
       └──── ② 数据通道（两条流在内存里对接） ◄─────────┘
```

- **命令通道**：APP 用 `POST /api/poll` 长轮询（25 秒一轮），服务端把 `counts` / `list` / `thumb` / `file` / `recv` / `disconnect` 交给 APP 执行。所以手机不需要开放任何端口，路由器和防火墙都不用配。
- **数据通道**：手机 → 电脑时，APP 把字节 `POST` 到服务端的一个 `PassThrough` 流，浏览器从 `/api/file` 同一个流里读走；电脑 → 手机时反过来。两端在内存里对接，**服务端不写磁盘、不建索引、不留副本**。
- **发现**：APP 向 UDP 8788 广播 `{"proto":"huchuan","type":"discover"}`，电脑回自己的 IP、端口、主机名。
- **会话**：注册后发随机 token，之后每个请求都带 token 并刷新活跃时间。心跳 10 秒一次；45 秒没动静判离线；120 秒清理会话；推送出去的文件 20 秒没人取、600 秒没确认保存就作废。

## 目录结构

```
server/          电脑端服务（index.js + lib/session.js 协议核心 + web/ 前端）
phone/app/src/   安卓源码（TransferService 是核心，负责长轮询与线程池）
test/            假手机与二维码解码小工具
tools/           桌面启动器脚本、图标生成、本地 gradle
启动互传.bat      双击启动
```

## 编译 APK

仓库里不带 gradle 发行包（268MB，太大），本机用一个即可：

```bash
cd phone
JAVA_HOME="/path/to/Android Studio/jbr" ../tools/gradle-8.5/bin/gradle assembleDebug
```

产物在 `phone/app/build/outputs/apk/debug/app-debug.apk`，服务启动后会把它挂到 `/api/apk` 上供手机下载（这个文件本身不进仓库）。改代码记得同步升 `phone/app/build.gradle` 里的 `versionCode`——Android 安装时版本号只增不减。

## 隐私与边界

- 只在局域网内工作：没有云端、没有账号、没有任何外发请求。
- 服务监听 `0.0.0.0`，同一网段的设备都能发现并连接，协议是 HTTP 明文 + 设备 token。这套是给自家网络用的，**不要放到公共/不可信网络里长期开着**。
- 停止服务后电脑端不留任何文件记录或缓存。

## 已知限制

- 国产系统（HarmonyOS / MIUI 等）会冻结后台进程，APP 切后台一段时间会看到「连接中断，3 秒后重连」——这是系统的省电策略，需要在系统设置里给本应用关掉电池优化。
- 真机只在 Huawei P60 Art（HarmonyOS 4 / Android 12）上验证过，其余机型靠 `test/fake-phone.js` 做的协议级联调。
- 「文件」「应用」两个分类还没开放；网页上的删除按钮未实现。
- 没有 iOS / iPad 端。
- 服务要手动启动，不做开机自启。
